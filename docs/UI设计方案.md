# UI 与动效优化设计方案（Apple 设计语言）

> 状态：**待审查**，尚未实施。
> 目标：在现有技术栈（Vue 3 + UnoCSS + TDesign 变量）上，把界面从"能用"推进到"顺手、耐看、有质感"。
> 范围：视觉令牌、组件手感、过渡动效。**不改信息架构、不改功能**。

---

## 0. 需要你先拍板的 5 件事

实施前需要你确认，不同选择对应的工作量和风险不同：

| # | 决策点 | 选项 A（推荐） | 选项 B | 影响 |
|---|---|---|---|---|
| 1 | 视觉改动幅度 | **只调令牌与动效，布局不动** | 连布局留白一起调 | A 风险低、一天可完成；B 需逐页复查 |
| 2 | 动效强度 | **克制**（iOS 原生级，150-260ms） | 明显（更大位移、更多回弹） | 决定是否引入 spring 回弹 |
| 3 | 是否引入背景模糊（毛玻璃） | **只用在浮层**（弹窗/抽屉/菜单） | 侧栏也用 | 模糊对低端机 GPU 有开销 |
| 4 | 字号阶梯 | **收敛到 7 档**（去掉 11.5/12.5/13.5 半像素档） | 保持现有 14 档 | 收敛会改动较多文本样式 |
| 5 | TDesign 组件是否一起改 | **先只改自研 Ui\* 与手写 CSS** | 连 TTable/TTabs 一起 | B 需要先做完 D 批迁移 |

本文档默认按 **A / 克制 / 浮层模糊 / 7 档 / 先自研组件** 展开。

## 1. 现状诊断（量化，不是感觉）

### 1.1 动效：令牌已定义，但 97% 没用上

`main.css` 里其实早就有一整套令牌：

```css
--mc-dur-fast: 120ms;  --mc-dur-base: 180ms;  --mc-dur-slow: 240ms;
--mc-ease-out: cubic-bezier(0.22, 1, 0.36, 1);   /* 很标准的重度 ease-out */
```

但全仓统计：

| 缓动写法 | 出现次数 | 说明 |
|---|---|---|
| `ease-out`（裸写） | **66** | CSS 默认值 `cubic-bezier(0,0,0.58,1)`：**起步太急、收尾拖沓**，没有 Apple 那种"快起缓停" |
| `ease` | 12 | 对称曲线，用于位移会显得"机械" |
| `linear` | 5 | 仅适合旋转/进度 |
| `ease-in-out` | 4 | — |
| `cubic-bezier(...)` 自定义 | 3 | 其中 2 处才是令牌 |

**结论**：动效"到处都有但不统一"，且主体用的是最廉价的默认曲线。这是"为什么界面感觉平"的第一原因。

时长也有 4 档混杂（100/120/140/160ms），没有任何语义区分。

### 1.2 排版：14 档字号，含 3 个半像素档

```
11px ×5   11.5px ×8   12px ×36   12.5px ×2   13px ×17   13.5px ×1
14px ×11  15px ×3     16px ×8    18px ×2     20px ×2    22px ×4
24px ×1   26px ×3
```

问题：
- **11.5px / 12.5px / 13.5px** 在 1x 屏上会落在半像素，边缘发虚；在 2x 屏上又和相邻档几乎无差别——**属于"调出来的档"，不是"设计出来的档"**
- 12px 用了 36 次（列表次要信息），13px 用了 17 次，两者只差 1px，视觉上分不出层级，却增加了认知噪音

### 1.3 圆角：变量与硬编码混用

```
var(--mc-radius-sm) ×18   var(--mc-radius-lg) ×11   999px ×10
var(--mc-radius-md) ×10   2px ×6   6px ×3   8px ×2   10px ×1
```

`--mc-radius-sm/md/lg` = 6/10/14px 已定义，但 `UiDialog`、`UiDrawer`、`UiTooltip` 的关闭按钮写死 `6px`，`UiPopup` 面板写死 `10px`，滑块轨道写死 `2px`——**同一视觉意图出现两种来源**。

### 1.4 间距：不是栅格系统

padding 取值 Top12：`14px ×11`、`10px ×10`、`12px ×10`、`4px ×9`、`16px ×8`、`24px ×6`、`8px ×6`、`3px ×5`、`6px ×4`、`9px ×3`、`28px ×3`、`32px ×2`。

`3px / 9px / 14px / 28px` 都不在 4pt 栅格上。它们不是错的，但**让"节奏"变得随机**——相邻模块的留白差 1-2px 时，人眼读作"没对齐"。

### 1.5 层次：只有 2 档阴影，浮层与卡片差异不足

```css
--mc-shadow-1: 0 1px 2px rgba(0,0,0,.24), 0 2px 8px -2px rgba(0,0,0,.28);   /* 卡片 */
--mc-shadow-2: 0 12px 32px -16px rgba(0,0,0,.5);                            /* 浮层 */
```

暗色下浮层与背景的分离主要靠阴影，但 `shadow-2` 的模糊半径大、透明度高，在小面积菜单上会显得"糊"；缺少中间一档（菜单/popover 级别）。

## 2. Apple 设计语言：可落地的 5 条（不是形容词堆砌）

从 Apple HIG 与 macOS/iOS 的实际实现里提炼，每条都对应上面的诊断：

### 原则 1｜层级靠"克制"，不靠"强调"

Apple 的界面里，同一屏内**只有一个视觉重心**。当前后台页一个问题：标记（tag）、链接、按钮、页签全是品牌色，导致"什么都在喊"。

> 落地：品牌色只用于 ①主操作按钮 ②选中态指示 ③未读。其余一律走灰阶。链接改用 `ink` + hover 下划线，而不是蓝色。

### 原则 2｜动效是"物理"，不是"装饰"

iOS 的过渡都有明确的空间关系（从哪来、到哪去）与惯性（快起缓停、可回弹）。当前 66 处 `ease-out` 的问题正是"没有物理感"——它既不是从某个方向来，也没有惯性。

> 落地：所有位移类过渡改用**重度 ease-out**（`cubic-bezier(0.22,1,0.36,1)`，已有令牌）；只有"回弹"场景（开关、滑块松手、拖拽释放）才用 overshoot 曲线。

### 原则 3｜连续曲率（squircle）

Apple 的圆角不是纯圆弧，而是 superellipse（连续曲率），视觉上"更饱满、不尖"。纯 CSS 无法真做 squircle，但可以用**圆角与尺寸的比例**逼近：小控件 6-8px、卡片 12-14px、模态 16-18px，且同一层级内保持一致。

> 落地：把圆角收敛成 4 档（6 / 10 / 14 / 20）+ 胶囊 999，删除所有硬编码。

### 原则 4｜排版的层级来自"字重 + 颜色"，不是"字号"

当前 14 档字号是在用尺寸硬撑层级。Apple 的做法是：**字号档少，靠字重（400/500/600）与不透明度（100%/70%/45%）拉开层级**。

> 落地：7 档字号 + 3 档字重 + 3 档前景不透明度，替代"再加一个 12.5px"。

### 原则 5｜状态要"能被感觉到"，但要安静

当前很多状态变化是瞬时的（hover 直接跳色、开关直接切换）。Apple 的做法是给**所有状态变化 120-180ms 的过渡**，让变化"看得见过程"。

> 落地：所有可交互元素必须有 `transition`，且统一走令牌。

## 3. 设计令牌重构（方案核心）

### 3.1 动效令牌

```css
/* 时长：3 档，按"感知"而非"数值"命名 */
--mc-dur-instant: 120ms;   /* 状态反馈：hover / 按压 / 颜色 */
--mc-dur-base:    200ms;   /* 位移：面板滑入 / 气泡入场 */
--mc-dur-slow:    280ms;   /* 大尺度：抽屉 / 模态 */

/* 缓动：3 条曲线覆盖所有场景 */
--mc-ease-out:   cubic-bezier(0.22, 1, 0.36, 1);    /* 默认：快起缓停，位移与淡入 */
--mc-ease-in-out: cubic-bezier(0.4, 0, 0.2, 1);     /* 对称：颜色 / 尺寸变化 */
--mc-ease-spring: cubic-bezier(0.34, 1.56, 0.64, 1);/* 回弹：仅松手 / 开关 / 拖拽释放 */
```

> 现有 `--mc-ease-out` 保留不动（已经是好曲线），新增 spring。删除 `--mc-ease-in`（只用在 1 处）。

### 3.2 字号阶梯（7 档）

| 令牌 | 值 | 用途 | 字重 | 前景 |
|---|---|---|---|---|
| `--mc-fs-caption` | 11px | 时间戳、辅助标注 | 400 | 45% |
| `--mc-fs-sm` | 12px | 列表预览、标签 | 400 | 70% |
| `--mc-fs-body` | 13px | 正文、消息、表单 | 400 | 100% |
| `--mc-fs-emphasis` | 14px | 消息昵称、列表标题 | 500 | 100% |
| `--mc-fs-title` | 16px | 卡片标题、面板标题 | 600 | 100% |
| `--mc-fs-heading` | 20px | 页面标题 | 600 | 100% |
| `--mc-fs-display` | 26px | 空态主标题、后台大数 | 600 | 100% |

**迁移映射**（半像素档的归并）：

| 原值 | 归并到 | 理由 |
|---|---|---|
| 11.5px | 11px 或 12px | 半像素；按"是否次要信息"二选一 |
| 12.5px | 12px | 差 0.5px 无感知 |
| 13.5px | 13px | 同上 |
| 15px | 16px 或 14px | 只 3 处，就近归并 |
| 18px | 20px | 只 2 处 |
| 22px / 24px | 26px | 空态标题与后台大数 |

### 3.3 圆角（4 档 + 胶囊）

```css
--mc-radius-sm:  6px;   /* 标签、小按钮、输入内元素 */
--mc-radius-md: 10px;   /* 按钮、输入框、列表选中态、菜单面板 */
--mc-radius-lg: 14px;   /* 卡片、气泡、面板 */
--mc-radius-xl: 20px;   /* 模态、空态卡片 */
--mc-radius-pill: 999px;/* 头像、开关、分页 */
```

删除所有硬编码 `2/6/8/10px`（滑块轨道的 `2px` 保留，它是"线"不是"面"，单独注释说明）。

### 3.4 间距（4pt 基准）

```
2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 / 40
```

迁移：`3→4`、`9→8`、`14→16`、`28→24` 或 `32`。共 **22 处**（`3px×5 / 9px×3 / 14px×11 / 28px×3`）。**这一项影响面最广，建议单独一批做**，且必须逐页截图确认没有挤压。

### 3.5 层次（3 档 elevation + 材质）

```css
/* 亮色 */
--mc-elev-1: 0 1px 2px rgba(15,23,42,.05), 0 2px 6px -2px rgba(15,23,42,.06);  /* 卡片 */
--mc-elev-2: 0 8px 24px -12px rgba(15,23,42,.18);                              /* 菜单/popover */
--mc-elev-3: 0 24px 64px -24px rgba(15,23,42,.28);                             /* 模态/抽屉 */

/* 浮层材质：半透明 + 背景模糊（Apple 的 .regularMaterial） */
--mc-material: color-mix(in srgb, var(--td-bg-color-container) 82%, transparent);
--mc-blur: saturate(180%) blur(20px);
```

浮层（弹窗/抽屉/菜单）改为 `background: var(--mc-material); backdrop-filter: var(--mc-blur)`，并配 `@supports not (backdrop-filter: blur(1px))` 回退到不透明。

## 4. 动效规范（逐组件，含具体参数）

### 4.1 滑块（你特别提到的）

当前问题：`input[type=range]` 原生行为，拖动时 thumb 无反馈，数值变化瞬时跳变。

| 状态 | 效果 | 参数 |
|---|---|---|
| hover | 轨道加粗 4→5px，填充色不透明度 100% | `180ms var(--mc-ease-in-out)` |
| 拖动中 | thumb `scale(1.18)`，轨道 5→6px | `120ms var(--mc-ease-out)` |
| 松手 | thumb 回弹到 `scale(1)`，带轻微 overshoot | `220ms var(--mc-ease-spring)` |
| 数值变化 | 右侧 `148px` 数字用 `tabular-nums`，切换时做 120ms 淡入（不是数字滚动，避免干扰） | `120ms` |
| 键盘微调 | 每次 ±1 时 thumb 有 80ms 短脉冲（`box-shadow` 扩散） | `80ms` |

> 实现要点：填充用 `background-size` 或 `::before` 的 `transform: scaleX()`（GPU 合成），**不用 `width`**（会触发布局）。

### 4.2 开关

| 状态 | 效果 | 参数 |
|---|---|---|
| 切换 | knob 位移 + 轨道颜色同时过渡 | `knob: 220ms var(--mc-ease-spring)`；`track: 180ms ease-out` |
| 按压 | 整颗 `scale(0.96)` | `100ms` |

> 当前 knob 用 `translate-x` 已是纯合成属性 ✓，只需换曲线。

### 4.3 按钮

| 状态 | 效果 |
|---|---|
| hover | 背景色变化 `120ms`（不加位移、不加阴影，Apple 按钮 hover 很安静） |
| 按压 | `transform: scale(0.97)`，`100ms var(--mc-ease-out)` |
| 松开 | 回 `scale(1)`，`180ms var(--mc-ease-spring)` |
| loading | 图标旋转 + 文字后缀淡入，按钮宽度**不跳变**（预先占位） |

### 4.4 模态与抽屉

| 元素 | 效果 | 参数 |
|---|---|---|
| 遮罩 | `opacity 0 → 1` | `200ms var(--mc-ease-out)` |
| 模态面板 | `scale(0.96) translateY(-8px) → 1/0` | `240ms var(--mc-ease-out)` |
| 抽屉面板 | `translateX(24px) → 0`（不是从屏幕外滑入，短距离更有质感） | `280ms var(--mc-ease-out)` |
| 背景页 | 打开时主区 `scale(0.98)`（iOS sheet 的层次感） | `280ms var(--mc-ease-out)` |

> 背景缩放是 Apple 很标志性的一招：让"浮层之下 ≠ 同一层"。**但要注意**：`transform` 会创建新的包含块，可能影响 `position: fixed` 子元素（如我们的右键菜单已 Teleport 到 body，安全）。

### 4.5 消息气泡

| 场景 | 效果 |
|---|---|
| 新消息入场 | `opacity 0→1` + `translateY(6px)→0`，`200ms var(--mc-ease-out)` |
| 发送中 | 气泡轻微 `opacity: 0.7`，确认后恢复（不做骨架屏，太吵） |
| 撤回 | 气泡高度收缩 + 内容淡出，`200ms`（需 `transition` 在 `max-height` 上，注意避免回流） |
| 右键菜单 | 从点击点 `scale(0.94)→1` + 淡入，`140ms`（当前已是，保持） |

### 4.6 列表与会话项

| 状态 | 效果 |
|---|---|
| hover | 底色淡入 `120ms`（不加位移，列表加了位移会"抖"） |
| 选中 | 底色 + 左侧指示条宽度 `0→3px`，`180ms var(--mc-ease-out)` |
| 未读红点出现 | `scale(0)→1` 弹入，`220ms var(--mc-ease-spring)` |

### 4.7 页签指示条

当前是直接跳到目标位置。改为：

```
indicator: transform: translateX() + width 过渡
参数: 240ms var(--mc-ease-out)
```

### 4.8 侧栏抽屉（已有的区域抽屉）

当前是 `translateX(±12px)` + 淡入。改为：

| 元素 | 效果 |
|---|---|
| 遮罩 | 从 `rgba(0,0,0,0)` 淡入到 `.16`，`200ms`；**同时**主区 `scale(0.995)`（极轻微） |
| 面板 | `translateX(-16px) → 0`，`260ms var(--mc-ease-out)` |
| 关闭 | 反向，`180ms`（关闭永远比打开快 30%，符合"响应快"的心理预期） |

## 5. 视觉细节清单

1. **大字号负字距**：`--mc-fs-display` / `--mc-fs-heading` 加 `letter-spacing: -0.02em`（Apple 的标题都略带紧排）
2. **数字等宽**：所有数值（时间、计数、尺寸）统一 `font-variant-numeric: tabular-nums`，避免跳动
3. **分隔线**：统一 1px 且用 `var(--mc-hairline)`；2x 屏可降为 `0.5px`（`transform: scaleY(0.5)`，注意不要用 `border-width: 0.5px`，Safari 会渲染成 0）
4. **滚动条**：暗色下用 `rgba(255,255,255,.12)`，宽度 8px，仅在 hover 容器时显现
5. **焦点环**：统一 `outline: 2px solid var(--td-brand-color); outline-offset: 2px`（当前各处不一致）
6. **图标尺寸**：统一 16 / 20 两档 + 线宽 1.5，删除 14/18/22 等杂值
7. **空态**：加一个 4px 的图标容器内边距与 `--mc-elev-1`，让卡片"浮"起来一点点
8. **头像**：加 1px 内描边 `inset 0 0 0 1px rgba(255,255,255,.08)`，暗色下与背景分离

## 7. 验收标准（可量化）

| 指标 | 现状 | 目标 |
|---|---|---|
| 裸 `ease-out` 出现次数 | 66 | **0**（全部走令牌） |
| 动效时长档位 | 4 档混杂 | **3 档**（120/200/280） |
| 字号档位 | 14 档（含 3 个半像素） | **7 档**（全整数） |
| 硬编码圆角 | 12 处 | **0**（滑块轨道除外，注释说明） |
| 非 4pt 栅格间距 | 22 处 | 0 |
| 浮层阴影档位 | 2 | 3 |
| 可交互元素缺 `transition` | 存在 | 0 |
| 亮/暗对比度（正文） | — | ≥ 4.5:1（WCAG AA） |
| `prefers-reduced-motion` 覆盖 | 部分 | 100% 动效均有降级 |

## 8. 我不建议做的（Apple 审美的常见误用）

1. **不加大面积毛玻璃**。Apple 只在"浮在内容之上"的表面用，侧栏/列表用会显得脏，且低端机会掉帧。
2. **不做弹性拖拽/物理惯性滚动**。聊天列表的滚动交给浏览器原生，自定义会破坏输入法与无障碍。
3. **不加"发光/渐变描边"等炫技效果**。当前界面已经偏"信息密度高"，再加装饰会更吵。
4. **不把动画时长拉长到 400ms+**。聊天是高频操作，超过 300ms 会明显感觉"卡"。
5. **不引入第三方动画库**（framer-motion / gsap）。现有场景用 CSS transition 足够，引入会把首屏 bundle 增大 30-60KB。

## 9. 参考实现（示意，不是最终代码）

