# 旧站（chat.modern-chat.top）→ 新站（newchat.modern-chat.top）迁移方案

本文是旧站迁移功能的实现契约，PHP 侧（旧站）与 Go 侧（新站）都必须严格按本文实现。
改动任何字段之前，先改本文并同步两侧。

## 1. 背景与目标

- 旧站 `chat.modern-chat.top`（PHP，数据库 `chat`）已弃用、仅维护。
- 新站 `newchat.modern-chat.top`（Go + Vue，数据库 `modernchat_nc`）。
- 用户在旧站登录后，`chat.php` / `mobilechat.php` 不再进入聊天界面，而是显示迁移向导：
  确认资料 → 核对消息 → 带进度迁移 → 删除已迁移的旧数据 → 用一次性 token+key 跳到新站 `/app/login` 自动登录。

## 2. 部署拓扑（本次改造后）

| 路径 | 内容 |
| --- | --- |
| `https://newchat.modern-chat.top/` | 官网（`modern-chat-new/website` 构建产物，hash 路由） |
| `https://newchat.modern-chat.top/app/` | 聊天前端（`modern-chat-new/web`，vite `base:'/app/'`，history 路由 base `/app/`） |
| `/api/`、`/ws`、`/uploads/`、`/_dl/` | 不变，仍由 Go 服务（127.0.0.1:8100）处理 |
| `/qiniu/<key>` | 反代到七牛 CDN 域名（私有空间，带 `?e=&token=` 的签名链接才能取到对象） |

对象存储（七牛）下载域名：**`https://modern-chat-new-cdn.chenfei.tech`**（bucket `modern-chat-new`，私有空间）。
换域名要同时改两处：`system_settings` 的 `storage.publicBase` 与 nginx 里 `/qiniu/` 的 `set $qiniu_host`。

## 3. 两侧共享配置

新站 `.env`（`/opt/modernchat-nc/app/server/.env`）新增：

```
# 旧站迁移：与 chat/migrate_config.php 中的 secret 必须完全一致（>=32 字节）
LEGACY_API_SECRET=<openssl rand -hex 32>
# 旧站库（只读）。迁移程序只读该库，不写。
LEGACY_DB_DSN=<只读账号>:<密码>@tcp(127.0.0.1:3306)/chat?charset=utf8mb4&parseTime=True&loc=Local
```

生产已配置为只读账号 `legacy_ro`（`GRANT SELECT ON chat.*`），不使用 root：
`LEGACY_DB_DSN=legacy_ro:<密码>@tcp(127.0.0.1:3306)/chat?charset=utf8mb4&parseTime=True&loc=Local`。

旧站 `chat/migrate_config.php`（新增文件）：

```php
define('MC_NEW_BASE', 'https://newchat.modern-chat.top');
define('MC_NEW_API', MC_NEW_BASE . '/api');
define('MC_MIGRATE_SECRET', '<同上 secret>');
define('MC_SKIP_ADMIN', false);      // 运维开关：管理员是否完全绕过向导（默认 false，管理员也走迁移）
define('MC_POSTPONE_SECONDS', 3600); // 管理员在向导页点「暂不迁移，先回旧站」后的放行时长
```

取值顺序是 `MC_MIGRATE_SECRET` → 环境变量 `LEGACY_API_SECRET` → 文件内常量默认值；
`mc_migrate_secret_ready()` 用于在向导里提示「未配置密钥」。

## 5. 数据映射（Go 侧写入 `modernchat_nc`）

关键规则（与 `service/migrate_write.go` 一致）：

### 5.1 迁移口径：只迁「本人」的数据

一次迁移只落一个人——**他的账号、他自己的消息、他加入的群**，不给旧站里没迁移的人建任何账号：

- 只创建迁移用户自己的 `users` 行；私聊对端、好友、群成员、群主都**不再补建账号**。
  （早期实现会给每个对端建占位账号，一次迁移能凭空多出几百个空用户，已废弃。）
- 好友：只有对端**已经迁过来**（`legacy_user_map` 里有映射）才写双向两行，否则跳过。
  对方后来自己迁移时，会由他自己的迁移补上这段关系。
- 群：群照建（`direct_key = "legacy-group:<旧群id>"` 作幂等键），迁移用户按旧站角色入群；
  其他成员只加已迁移的；群主本人没迁移时，群主暂时落在迁移用户身上（避免出现无主群）。
- 私聊消息：仅当对端已迁移时才落库并建会话，否则整段跳过——没有账号的人无法作为会话参与方。
- 群聊消息：按**发送者映射**落库，发送者没迁移的消息跳过（不再整段记成迁移用户发的）。
- 进度按「扫描过的行数」推进，跳过未映射的消息不会让百分比卡住。
- 迁移完成后自动加入默认群「公共聊天室」（`EnsureDefaultGroup` + `AddMembersIgnoreDuplicate`），
  再生成 `user_conversations` 行（未读清零）。
- 由此带来的可见后果：**对端还没迁移时，双方私聊记录在新站暂时看不到**；等对方迁移后，
  由对方的迁移把这段会话和两个方向的消息一起带过来。

### 5.2 字段映射

- 旧密码 bcrypt `$2y$` 原样复制到 `users.password_hash`（Go 的 `x/crypto/bcrypt` 可直接校验 `$2y$`）。
- username 清洗/截断到 20 字符，重名追加 `_<legacyId>`；email 冲突时留空；`email_verified=1`。
- 头像相对路径改写为 `https://chat.modern-chat.top/chat/<path>`，外链保留，`default_avatar.png` 置空。
- 文件类消息转占位文本 `【文件未迁移】<file_name>`；`is_deleted=1` → `is_recalled=1`；
  保留 `created_at`；`client_msg_id = legacy-<旧id>`。

### 5.3 发送守卫（WebSocket）

`internal/ws/dispatch.go` 的 `handleChat` 在落库前拦两类消息：

- 会话不存在（群已解散 / 只剩历史引用）→ 「会话不存在，无法发送消息」。
- 单聊对端在新站没有账号（旧站没迁移过来）→「对方还没有注册或迁移到新版聊天室，暂时无法发送消息」。

## 6. 旧站改造（PHP）

新增 `chat/migrate.php`（向导 UI）、`chat/migrate_api.php`（session 鉴权 + 转发新站 + 完成后删旧数据）、
`chat/migrate_config.php`（配置）、`chat/migration_guard.php`（守卫）。

守卫插入点：`chat.php` 的 `$user_id = $_SESSION['user_id'];` 之后、
`mobilechat.php` 登录校验之后，各一行 `require_once __DIR__ . '/migration_guard.php';`。
守卫在 CLI 下直接 return；未登录交给原跳转；其余用户一律渲染向导并 `exit`。
**管理员判定必须用 `users.role = 'admin'`，不要用 `users.is_admin`**——旧库这个字段有大量误标
（573 个普通用户里 4 个是 `1`），用它会让普通用户被当成管理员而漏掉向导；判定结果缓存在
`$_SESSION['mc_is_admin']`。管理员同样进入向导（`MC_SKIP_ADMIN` 默认 `false`），向导页底部为其
渲染「暂不迁移，先回旧站」链接（`?mc_postpone=1`），点一次写入 `$_SESSION['mc_postpone_until']`，
在 `MC_POSTPONE_SECONDS` 内直接回旧站界面，到期自动恢复提示。

`complete` 成功后在**单个事务**里删除该用户在旧库的数据（`users` 行保留，避免用户名被抢注）：
`messages`、`group_messages`、`friends`、`group_members`、`files`、`unread_messages`、`mentions`、`sessions`。
逐表 `DESCRIBE` 探测，缺表跳过（不同旧站版本表结构有差异）。

## 7. 新站前端（`/app/`）

1. `web/vite.config.ts` 的 `base: '/app/'`；`api/client.ts` 的 `redirectToLogin()` 等硬编码 `/...` 路径
   全部改为 `import.meta.env.BASE_URL` 前缀。
2. `/app/login?token=..&key=..&migrated=1`：`AuthView.vue` 挂载时若带这组参数，
   调 `POST /api/auth/migrate-login`，成功即 `applyAuth` + `router.replace('/chat')`，
   并弹出一次性提示「迁移完成，由于部分用户没有注册，您可能无法向对应用户发送消息，请谅解。」
   （失败则提示「自动登录链接已失效，请用原密码登录」）。
3. 管理员后台新增「群聊管理」页签：群列表（名称/群主/成员数/消息数/创建时间/搜索/分页）
   + 点击查看群消息（分页、按发送者/内容搜索）+ 封禁 / 解封 / 解散 / 踢出成员四个管理动作
   （列表行与抽屉里都有入口，危险操作走二次确认弹窗，成功后重新拉取列表与详情）。

## 8. 后台群聊管理接口（新站）

`GET /api/admin/groups?q=&page=1&size=20`
→ `{ "total": 14, "items": [{ "id": 3, "name": "群名", "ownerId": 1, "ownerName": "xuminghao",
   "memberCount": 12, "messageCount": 340, "createdAt": "..." }] }`

`GET /api/admin/groups/:id`
→ `{ "id": 3, "name": "...", "ownerId": 1, "ownerName": "...", "memberCount": 12,
   "messageCount": 340, "createdAt": "...", "announcement": "", "members": [{ "userId": 1,
   "username": "xuminghao", "nickname": "...", "role": "owner", "joinedAt": "..." }] }`

`GET /api/admin/groups/:id/messages?before=<messageId>&size=50&q=`
→ `{ "items": [{ "id": 900, "senderId": 2, "senderName": "xmh", "content": "...",
   "msgType": "text", "createdAt": "...", "isRecalled": false, "adminDeleted": false }],
   "hasMore": true }`

列表/详情额外返回 `banned`、`bannedAt`、`banReason` 三个字段。

写操作（都要 `role=owner` 或 `role=admin`，且只接受群聊 `type=2`，单聊一律 404）：

`POST /api/admin/groups/:id/ban`，body `{ "reason": "违规内容" }`（可为空）
→ `{ "ok": true, "banned": true }`。封禁后**群内所有人（含群主）都不能发消息**，
WebSocket `handleChat` 会直接回「该群已被管理员封禁，暂时无法发送消息」；与群内
自己的「全员禁言（mute_all）」是两套东西——禁言时群主/管理员仍可发言，封禁则一律拦住。

`DELETE /api/admin/groups/:id/ban` → `{ "ok": true, "banned": false }`（解封，清空三列）。

`DELETE /api/admin/groups/:id` → `{ "ok": true }`。解散是**硬删除 + 事务级联**：
按 500 条一批清掉该群消息的 reactions / favorites / deletions / reports（这些从表没有外键），
再删 messages、conversation_members、user_conversations、conversation_files、
conversation_invites，最后删 conversations 行；事务内完成，失败整体回滚。

`DELETE /api/admin/groups/:id/members/:userId` → `{ "ok": true }`。
踢出会同时删 `conversation_members` 与 `user_conversations`（该用户列表里不再有这个群）；
**踢掉群主时 `conversations.owner_id` 置 NULL**（群不会因此解散）；成员不在群里返回
404 `{ "error": "该用户不在这个群里" }`。

四个动作都写审计（`admin_audits`，target_type=`group`，action 为
`ban_group` / `unban_group` / `dissolve_group` / `kick_group_member`），
参数非法时先拒绝、不查库（`群聊 id 不合法` / `用户 id 不合法` / `请求格式不正确`）。

三条保护（列表/详情的 `default` 字段供前端隐藏入口，接口侧同样拦截）：

- **默认群「公共聊天室」不能封禁、不能解散**：它是注册与旧站迁移的落地群，封禁会让新用户
  一进站就发不出话，解散更会让后续注册/迁移没有去处。接口回 400
  `公共聊天室是默认群，不能封禁` / `公共聊天室是默认群，不能解散`；列表与详情返回
  `"default": true`，前端据此隐藏封禁/解散按钮，只保留查看。
- **不能把自己踢出群聊**：`userId == 当前登录管理员 id` 时回 400 `不能把自己踢出群聊`。
- **管理员之间不能互踢**：只有站长（`role=owner`）能踢管理员；普通管理员踢管理员回 400
  `不能踢出管理员`。踢普通用户不受限制。前端成员行的「踢出」也按同一口径收敛
  （群主行、自己的行不显示；管理员行只对站长显示）。

## 9. 迁移表（迁移 0029 / 0030）

生产库已有 0026/0027/0028 三个迁移，本次迁移文件编号为 **0029_legacy_migration**，
建三张表：`legacy_user_map`（旧 id → 新 id）、`migration_jobs`（任务与阶段进度，含排除列表）、
`migration_sso_tokens`（一次性票据，只存 sha256）。服务启动时 `MIGRATE=true` 由
`store.RunMigrations` 按 `file://migrations` 自动执行。

**0030_admin_group_actions** 给 `conversations` 加三列：`banned_at datetime(3)`、
`banned_by bigint unsigned`、`ban_reason varchar(120)`。同一 `ALTER` 里加三列，
不要拆成多条语句——golang-migrate 的 MySQL 驱动没开 `multiStatements`，会报语法错误。

## 10. 上线顺序（已验证）

1. 备份新站库与旧站目录：`mysqldump` + `tar czf`（旧站整目录约 2.5 MB）。
2. 新站：更新代码 → 服务器上 `go build`（`/usr/local/go/bin/go`）→ 替换
   `/opt/modernchat-nc/bin/modernchat-server` → `systemctl restart modernchat-nc`
   （启动即执行 0029 迁移）。
3. 静态：官网 `website/dist` 放站点根，聊天 `web/dist` 放站点根下的 `app/`，`chown -R www:www`。
4. nginx：`/app/` 段（SPA 回退 + index.html/sw.js 禁缓存）、`/qiniu/` 反代（`resolver` + 变量形式，
   否则该域名解析失败会让 `nginx -t` 直接报 emerg）、`/api` `/ws` `/uploads` 保持不动。
5. 旧站：上传 4 个新 PHP 文件 + 改过的 `chat.php` / `mobilechat.php`，
   用站点实际 PHP 版本（8.2，`/www/server/php/82/bin/php`）跑 `php -l`。
6. 验证：`/`、`/app/`、`/api/health` 200；旧站登录后出现向导；`migrate_api.php` 的
   `preview` 能返回真实统计；`complete` 拿到的 `loginUrl` 在 `/app/login` 能自动登录且票据只能用一次。
7. 迁移是**每个用户首次登录时各迁各的**，新站不会预先灌入数据。
