# Changelog

This file records the important changes of ModernChat. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versioning follows [Semantic Versioning](https://semver.org/).

> The project is currently in the `0.x` stage; in `0.MINOR.PATCH`, an increment of MINOR indicates potentially incompatible changes.

---

## [Unreleased]

### Added

- **Configurable Docker build image sources**: `server/Dockerfile` gains four build args, `GO_IMAGE` / `RUNTIME_IMAGE` / `GOPROXY` / `APK_MIRROR`, overriding the base image, the Go module proxy and the Alpine package mirror respectively; all defaults stay on the official sources (behaviour is unchanged when nothing is passed); `docker-compose.yml` forwards them, and the README and ops manual add examples for networks in mainland China (verify the trustworthiness of third-party mirrors yourself).

### Fixed

- **Compatibility for existing users and logout cleanup after `/uploads` switched to cookie auth**: the `mc_auth` cookie used to be issued only in responses to authenticated REST requests, so existing users (JWT in localStorage, no cookie in the browser) had a window where images did not load. Login/register responses and the WS handshake (clients always reconnect after a deployment restart) now grant the cookie, and it is also re-issued when files are fetched with an `Authorization` header; on a normal browser refresh the first-screen `GET /api/me` still obtains the cookie automatically, so **no re-login is needed and old message URLs need no migration**. In addition, `POST /api/auth/logout` is added (unauthenticated, available in maintenance mode) to clear the HttpOnly cookie; the frontend calls it on logout, so a browser can no longer open `/uploads` directly for 7 days after signing out. **API changes**: one optional endpoint added; the request/response structures of all existing endpoints are unchanged.
- **Friend relationships / email verification codes lacked unique constraints (minor)**: concurrent friend requests could insert duplicate rows in the same direction (duplicate people in the request/friend lists), and the email-code "check cooldown → insert" was not atomic, so multiple valid codes could exist for one email at the same time and the 60-second cooldown could be bypassed. Now `friends (user_id, friend_id)` and `email_codes (email, purpose)` have unique indexes; accepting a friend request upserts the reverse record (avoiding index conflicts when both sides send requests), and code issuance uses a row lock inside a transaction plus an in-place reset of a single row. **Upgrading requires migration 0025** (the migration first cleans up duplicate rows in the same direction, keeping accepted > pending > rejected and, within the same status, the earliest row). The API contract is unchanged (concurrent duplicate requests still return 409).
- **Audit logs truncated by bytes (minor)**: `Detail[:500]` / `TargetName[:120]` sliced by bytes, so Chinese text could be cut mid-character, producing garbled text in the database or errors in strict mode; they are now truncated by character (rune).
- **Web Push unsubscribe allowed privilege escalation (minor)**: the unsubscribe endpoint deleted by endpoint only, so any signed-in user who knew someone else's endpoint could unsubscribe them. It is now scoped by `user_id + endpoint`; unauthorized requests affect 0 rows. Server-side cleanup of expired endpoints still deletes by endpoint. **API contract unchanged** (request parameters unchanged, behaviour tightened only).
- **Catch-up messages after reconnect lacked reply summaries (minor)**: the `AfterID` incremental endpoint used on reconnect did not attach the `reply` summary (first-screen pagination did), so quote blocks in incremental messages stayed blank until the next refresh. The catch-up path now calls `AttachReply` as well.
- **HTTP server lacked timeouts (minor)**: `http.Server` only set Addr/Handler and no `ReadHeaderTimeout`, so a slow sender could hold a connection open indefinitely (Slowloris); idle keep-alive connections had no reclamation limit either. `ReadHeaderTimeout=10s` and `IdleTimeout=90s` are added; **`ReadTimeout/WriteTimeout` are deliberately not set** (WebSocket and file upload/download are long-lived connections, so an overall timeout would kill legitimate sessions).
- **WS handshake token reached access logs via the query string (minor, contract unchanged)**: `?token=` is kept for compatibility with the existing frontend, and a same-origin `mc_auth` cookie fallback is added — the frontend can later handshake without a token, keeping it out of reverse-proxy/access logs. **This item only adds a compatibility path**; handshake parameters and frame formats are unchanged, and no frontend change is required.
- **Email verification silently skipped when SMTP is not configured (minor, behaviour tightened)**: previously, when a site enabled "email verification required at registration" but SMTP was not configured, registration was downgraded to verification-free, letting attackers bypass the site policy. Now, except for the first account (deployment bootstrap), this case returns 503 "mail service not configured, please contact the site admin". **Behaviour change**: registration fails rather than succeeds in this misconfigured state; correctly configured sites, or those with the switch off, are unaffected.
- **Thumbnail decoding had no size limit (decompression bomb, medium)**: thumbnail generation called `image.Decode` on the whole image, so a few-KB image header declaring huge dimensions made the decoder allocate memory per the declared size (e.g. 20,000 × 20,000 is about 1.6 GB), potentially OOMing the process. It now first uses `image.DecodeConfig` to read the header only and skips thumbnailing (the frontend falls back to the original image) when the pixel count exceeds 40 million (about 6325×6325), plus a `recover` around the whole thumbnail path so a malformed image that panics the decoder only logs and does not affect uploads.
- **Site-wide announcements were multi-step writes without a transaction (medium)**: `Announce` performed five independent writes in sequence — get/create the system conversation, backfill members, write the message, create inboxes for everyone, increment unread — and a mid-way failure left a permanent inconsistency ("message stored but members/inboxes not updated"), while an unread-increment failure only logged and kept broadcasting. `ConversationStore.Announce` now completes all steps in a single transaction; any failure rolls back entirely and nothing is broadcast. It returns 400 when there are no users (API and frontend contracts unchanged).
- **Last-site-admin protection had a concurrency hole (medium)**: `SetRole` was "`CountByRole` first, then `Save`", so two site admins demoting each other concurrently both saw 2 remaining and both succeeded, leaving no admin at all. `UserStore.SetRole` now locks all admin rows with `FOR UPDATE` in id order inside a transaction, making the demotion check and the write atomic; concurrent requests are serialized and the second receives "at least one site admin must be kept". API and frontend contracts unchanged.
- **`MarkRead` cursor could move backwards (medium)**: the condition kept `unread_count > 0` as a safeguard for inconsistent historical data, but the update wrote `last_read_message_id = upToID` directly — reporting a smaller id from a client pulled the cursor back, making historical messages unread again and duplicating pages when fetching new messages. It now uses `GREATEST(last_read_message_id, upToID)`, so the cursor only moves forward; clearing unread and removing @ marks behave as before.
- **Auto-update "false success" and tar extraction path traversal (medium)**: on a sha256 anomaly it only logged and `return`ed, while the outer defer still set phase to `done`, so the UI showed a successful update that never replaced anything; release extraction relied on external `tar -xzf`, so `../`, absolute paths or link entries in a malicious/corrupt package could write outside the install directory. It now calls `fail` and aborts on hash anomalies; extraction is done in Go, validating per entry that paths stay within the target directory, rejecting symbolic/hard links, capping the total extracted size at 1 GB, and adding regression tests for normal and malicious packages.
- **Password reset token TOCTOU, verification-code attempt counter not atomic (medium)**: `PasswordResetStore.Use` only did `Update("used", true)` without checking whether the token was still valid, so two concurrent requests with the same link could both change the password; email verification code failure counts were read-modify-write, so concurrent wrong submissions lost counts and the 5-attempt limit could be bypassed. Token consumption is now a conditional update inside a transaction (`used=false AND expires_at>now`), with `RowsAffected=0` returning `ErrResetTokenUsed` and the API replying 400 "reset link is no longer valid"; codes now use a single atomic UPDATE (`attempts = attempts + 1`, writing `used_at` when the limit is reached).
- **Web Push had no concurrency cap, no timeout, and arbitrary endpoints (medium)**: `webpush-go` uses an `http.Client` without a timeout by default, so an unresponsive endpoint ties up a connection for a long time; broadcasts to large groups started one unbounded goroutine per recipient; the subscription endpoint only checked the `https://` prefix, so it could be set to an intranet address (server-side SSRF). Now: ① the push client has a fixed 10s timeout; ② at most 16 pushes run globally, and beyond that they are dropped immediately (the message is already in the database); ③ the endpoint must be https, with no userinfo, and its host must belong to a mainstream browser push gateway (FCM / Mozilla / WNS / Apple); the subscription endpoint and the sending side share the same validation. **Note**: self-hosted/private push gateways are not on the whitelist; to support them, add domains to `service.pushEndpointHosts`.
- **Message sending was multi-step without a transaction and broadcast on failure (medium)**: `Create / UpsertInbox / BumpUnread / MarkMention` each used a separate connection and continued fan-out after only an `slog` on failure, producing "message stored but inbox last/unread not updated" and clients receiving messages that don't match the database. `MessageStore.CreateWithInbox` now commits all four steps in one transaction; any failure rolls back entirely and reports to the client via an error frame without broadcasting.
- **Concurrent direct-chat creation produced duplicate conversations (medium)**: direct-chat creation was four steps — check for an existing conversation, create the conversation, add members, initialize inboxes — with no transaction and no unique constraint, so a double click or both sides initiating at once could create one conversation each, after which messages/unread split across the two. A unique index `conversations.direct_key` (`smallID:largeID`) is added, and `EnsureSingle` wraps the lookup, conversation creation, member addition and inbox initialization in one transaction; with concurrent inserts only one succeeds, and the loser rolls back and reuses the existing conversation. **Upgrading requires migration 0024**; existing direct chats keep `direct_key` NULL (existing data is unaffected; only new conversations write it).
- **SSRF DNS rebinding in plugin installation from a URL (medium)**: `plugin.Fetch` validated with `LookupIP` first, then let `http.Client` re-resolve and connect, so an attacker could make the two lookups return different addresses (public at validation, intranet at connection). Validation and connection now both happen inside a custom `DialContext`: after resolving, it dials the already-validated IP directly, every redirect hop is controlled the same way, and environment proxies are explicitly disabled. The reserved ranges now also cover `100.64.0.0/10` (CGNAT), `192.0.0.0/24`, `198.18.0.0/15`, `240.0.0.0/4`, the documentation ranges, NAT64 `64:ff9b::/96` and IPv4-mapped addresses.
- **"Log out of all devices" didn't kick connected WS connections, and most uplink frames didn't re-check connection state (medium)**: `LogoutOthers` only bumped `token_version+1`, so established WebSockets still cached the old tv and could keep sending/receiving; in `Dispatch` only the `chat` frame re-checked bans/tv, while `typing/read/recall/edit/reaction/delivered/ping` all bypassed it. Now: ① "Log out of all devices" and a successful password reset via email actively `KickUser` and disconnect all connections; ② `Dispatch` uniformly re-checks bans and `token_version` before routing any frame, replying with an error frame and disconnecting on failure — after the handshake, every frame revalidates the connection state (the user exists, `token_version`, not banned, maintenance mode). The handshake/API contract is unchanged (frame formats unchanged; only the new `kicked` disconnect behaviour is added).
- **Single-message length limit didn't match the column width (medium)**: the admin console allowed "single message length" up to 5000 characters, but `messages.content` was `VARCHAR(1000)` — long messages errored with 1406 in strict mode and were silently truncated otherwise. Migration `0023` widens the column to `TEXT` (5000 multi-byte characters is about 15KB, well below the 64KB limit), and the GORM model is changed to `type:text` accordingly. **Upgrading requires migration 0023**; rolling back to `VARCHAR(1000)` would truncate over-long messages, so back up first.
- **`/uploads` was unauthenticated, listed directories and was publicly cached for a year (severe)**: the upload directory was open to all anonymous requests, and Gin's `StaticFS` also listed directory contents, so private images/voice/video could be enumerated; responses carried `public, max-age=31536000, immutable` and stayed in proxies/shared caches for a long time. Now: ① directories always return 404 (`onlyFilesFS`); ② caching becomes `private, max-age=3600` together with `X-Content-Type-Options: nosniff`; ③ reading requires login — the `Auth` middleware issues a same-origin `HttpOnly` cookie alongside authenticated responses, and `/uploads` accepts both `Authorization: Bearer` and the same-origin `mc_auth` cookie (the `UploadAuth` middleware returns 401 when not signed in and 403 when denied), so old URLs in historical messages keep working without migration; ④ under maintenance mode it is controlled like the API (administrators may access). **Trade-offs and limits**: per-conversation membership checks are not implemented (file URLs carry no conversation information and would need a new file-ownership mapping table), so a signed-in user who knows a URL can still read it; with S3 object storage, files are governed by bucket policies/CDN and are outside this middleware.
- **Attachment GC wrongly deleted videos and thumbnails (severe)**: the ops "clean orphan attachments" action only counted `image/audio/sticker` messages as references, while the frontend already supported sending videos, so in-use videos were bulk-deleted; image derivative thumbnails (`xxx_t.jpg`) were also judged orphans individually. It now collects all messages whose `content` starts with `/uploads/` (no longer enumerating by `msg_type`, so future message types are not missed), and thumbnails follow the original file's lifecycle; regression tests cover both dryRun and real deletion modes.
- **All streaming uploads dropped the first 512 bytes (severe)**: `LocalStorage.SaveStream` / `S3Storage.SaveStream` used `io.ReadFull` to read the file header for type sniffing and then wrote only the remainder to the temp file, never writing the first 512 bytes back; the S3 branch's `PutObject` also used the remaining length. The result was images that wouldn't open, silent voice messages and videos with only their second half (files smaller than 512 bytes failed outright). The header is now written back and the upload length uses the total including the header, with byte-for-byte round-trip regression tests for both the local and S3 branches.
- **Live nickname/avatar sync didn't work**: the server had been broadcasting `user_change`, but the frontend `ServerFrame` didn't declare it and had no handler, so peers' nickname/avatar changes needed a page refresh. `stores/ws.ts` now dispatches it centrally, updating direct-chat peers, group member caches, friends/requests lists and the user's own other devices.
- **Own messages didn't update the conversation list**: the sender's own client never receives the "brand-new message" `conv_change`, and the message echo branch missed `lastMessageId/At/Preview/Type`, leaving list preview, time and ordering on the previous message; the incorrect "record the read watermark on send" optimization is also removed, so forwarding a message into a conversation that still has unread messages no longer leaves the server-side unread count permanently stuck.
- **WS 4 KB uplink limit broke long messages**: `chat.maxMessageLength` allows up to 5000 characters (over 4 KB in UTF-8); the old `maxMsgSize=4096` made legitimate long messages hit gorilla's read limit, closing the connection without an `error` frame; the limit is now 64 KB.
- **New group members saw "no messages"**: `initInboxes` only inserted an empty inbox row without syncing the current latest message, while opening the conversation showed history. Joining actively / being invited / registering into the public group now writes the latest message preview and time and advances `last_read` to the latest message (historical unread is not retroactively counted).
- **`FRONTEND_URL` with only blank entries panicked password recovery after startup**: a value like `FRONTEND_URL=","` or all spaces parsed to nothing, the WS Origin whitelist rejected every browser origin, and `Forgot` indexing `FrontendURLs[0]` went out of range. Startup now fails with a hint that at least one origin must be configured (with a unit test).
- **Release version drift**: `web/package.json` / `web/package-lock.json` were stuck at `0.10.2`, while the website `website/package.json`, `package-lock.json` and the homepage Hero badge were stuck at `0.9.0`, inconsistent with the `0.10.3` already set in the CHANGELOG. All are now aligned to `0.10.3`; `scripts/check-version.sh` is added (it checks each package version and the website badge against the latest official version in the CHANGELOG and hints at the latest git tag), and the release process is documented in the README and ops manual.
- **Docker image version was always `dev`**: `server/Dockerfile` only passed `-s -w` at build time without injecting ldflags, so `/api/version` always returned `dev` under `docker compose`. Three build args `VERSION` / `COMMIT` / `BUILD_TIME` are added (`docker-compose.yml` already forwards them; they fall back to `dev` / `unknown` when unset); they can be passed in even when the build context has no `.git`, with no need to mount repository metadata just for the version.
- **Plugin sandbox never started in Chrome (severe)**: `mountRuntime` wrote the document into an iframe with `sandbox="allow-scripts"` (no `allow-same-origin`) via `contentWindow.document.open/write`, but parent-page writes to that window's document are rejected with `SecurityError`, so plugin code never executed — `__mcActivate` never fired and panels, message renderers, the sidebar and message actions all failed. It now injects via `iframe.srcdoc = bootHtml(code)`, **keeping the isolation without `allow-same-origin`** (plugins still cannot read the JWT or localStorage); the `ev.source !== iframe.contentWindow` origin check remains effective under `srcdoc`. Verified with a minimal plugin stub: `__mcActivate` runs normally, and bidirectional `postMessage`, event dispatch and RPC all pass.
- **Privilege leaks exposed once the sandbox started (medium)**: the `message:new` / `message:recall` / `presence` broadcasts were not filtered by recipient, so a plugin declaring only `ui:actions` could receive full message bodies; they are now filtered by `permissions.includes('message:read')`, and `runMessageAction` sends plugins without `message:read` only message metadata (id / conversation / sender / type / time / recall state).
- **The sandbox had no CSP, so plugins could bypass `allowed_hosts` with a bare `fetch` (medium)**: the boot HTML now injects `Content-Security-Policy` (`default-src 'none'`, scripts/styles inline only, `connect-src` limited to hosts declared by the `net` permission, frame/object/worker/form disabled), which is what finally makes the `net` host whitelist effective.
- **Realtime messages stopped conversation history from loading (medium)**: "first screen already loaded" was judged by whether `messagesByConv[convId]` existed, so a WS message for an unopened conversation created the array and opening it skipped history fetching (appearing as "history is gone"). A separate `loadedFirstPageByConv` flag now distinguishes "fully loaded" from "incremental only".
- **First-screen REST results overwrote concurrent WS messages (medium)**: the first-screen response assigned the whole list directly, so messages arriving during the `await` were overwritten until the conversation was reopened; the first screen now goes through `mergeServerPage` too.
- **Catch-up after disconnect was out of order (medium)**: gap messages filled in by `catchUp` had ids smaller than the loaded latest page, and appending them put old messages after the newest ones; merged results are now sorted by id (pending fixed at the end), so even a backlog larger than one page stays ordered.
- **`fetchMe()` failure left the chat page half-dead (medium)**: non-401 failures (offline / 502 / timeout) threw directly in `onMounted`, so the conversation list, notification listeners and plugin host never initialized and only a refresh helped; it is now wrapped in its own try/catch with a retryable "Reload" entry at the top, and frame listeners and shortcuts are bound only after successful bootstrap and never registered twice.
- **Logging out didn't coordinate with WS and the server (medium)**: the local `logout()` only cleared localStorage while the in-memory Pinia auth state and the WS connection kept receiving messages; `logout()` now tells subscribers to disconnect the WS, and the `api/client` 401 branch clears the store too. **Note**: the backend has no "single-session logout" endpoint (only `POST /api/me/logout-others`), so no server call was added and the API contract remains unchanged.
- **Read watermark recorded before sending (medium)**: `markRead` wrote `lastReportedRead` before sending the frame; when the WS was not connected `sendFrame` returned false and the frame was dropped, and `resync` after reconnect didn't resend it either, so server unread could never be cleared; the watermark is now recorded only after a successful send, and resent automatically after catch-up on reconnect.
- **Old socket `onclose` marked the new connection (medium)**: when switching pages quickly the old connection was CLOSING, and after `connect()` created a new connection the old callback still set `connected` to false, cleared the online list and scheduled another reconnect; each callback now checks `ws === socket` first, and `disconnect()` detaches the reference before closing.
- **Plugin API bare `fetch` had no timeout and no 401 handling (medium)**: code downloads, octet-stream uploads and install-by-URL stayed pending forever when a proxy hung, and 401 didn't return to the login page; they now use the new `rawFetch` (15s timeout, 60s for uploads, with Bearer and a synchronous logout on 401).
- **Message cache only grew**: the per-conversation local cache keeps the latest 800 messages, and trimming keeps `hasMore=true` so older history can still be paged up.
- **`read` frames from other devices cleared unread unconditionally**: unread is cleared only when `upToId` covers the newest message on this device, avoiding clearing messages this device hasn't seen.
- **Desktop notifications had a fixed tag**: tags are now set per conversation, so notifications from different conversations no longer overwrite each other and only the latest remains for the same conversation.
- **Cache usage copy was inaccurate**: the number from `navigator.storage.estimate()` minus localStorage also includes IndexedDB and other storage, while clearing only deletes PWA static caches; the copy now says "approximate site storage; clearing deletes static caches only".
- **Fire-and-forget without catch**: notification-click opening a conversation, group member refresh, notification permission requests and the `?panel=plugins` redirect now have `.catch`, avoiding unhandled Promise rejections.
- **Uploads shared a boolean flag**: images / videos / voice shared `uploading`, so with concurrent uploads the first to finish re-enabled the input early; it is now a concurrency counter.

## [0.10.3] — 2026-11-06

### Added

- **Release-based install and update (no compiling on the server)**: `scripts/package-release.sh` is added — after tagging on a build machine it produces `modernchat-<version>-linux-{amd64,arm64}.tar.gz` + `.sha256` in one step (containing the backend binary, frontend dist, migration SQL, nginx template and update script), uploaded as Gitee / GitHub Release assets. `scripts/install.sh` now downloads and installs from Releases (sha256 verified), so the server **needs neither Go / Node nor git**; `RELEASE_SOURCE=gitee|github` selects the source and `RELEASE_TAG` pins the version. The release package ships `scripts/update.sh` (CLI: query the latest Release → download and verify → atomic replacement → graceful restart). The site admin console's "online update" also supports release mode: it checks for new tags from the Release source recorded at install time, then downloads, verifies, replaces and restarts (source git deployments still use the local build mode).
- **Graphical updates in the admin console (online update tab)**: the admin console gains an "Online update" tab — check for updates (compares with `origin/main` and shows the latest tag and commit), one-click update (pull the latest code → build frontend and backend locally → atomically replace artifacts → restart the current instance automatically), with live logs streaming in the tab (polling every 2 seconds while in progress). Safety boundaries: only the site admin can trigger it, all commands use fixed arguments (branch locked to `origin/main`, no user input accepted), operations are audited (`web_update`), it is available only for systemd deployments from install.sh (Docker / bare-metal UIs point to the script instead), and `WEB_UPDATE=false` disables it entirely. New endpoints `GET /api/admin/update/{status,check}` and `POST /api/admin/update/start`.
- **Install/uninstall system improvements**: ① full logging — installs to `/var/log/modernchat/install-*.log` and updates to `logs/update-*.log` in the repo (both with a latest symlink); ② resume after interruption — rerunning the same command after a failed install automatically skips completed stages and doesn't ask for parameters again (progress stored in `/var/lib/modernchat/install-state`, mode 600), and `FORCE=1` reruns everything; ③ panel path adaptation — automatically detects the nginx binary and vhost directory of BT Panel (`/www/server/panel/vhost/nginx`) / 1Panel / OpenResty, writes the config and reloads directly, and can be specified manually when detection fails; ④ complete uninstall `scripts/uninstall.sh` — stops the service and removes the unit, deletes only nginx configs with the generated marker, keeps the database and install directory by default pending confirmation, and supports `AUTO_CONFIRM` / `PURGE_DB` / `DELETE_FILES` for non-interactive use.
- **Hot update (zero-downtime upgrade)**: `scripts/update.sh` defaults to blue-green two-instance switching — the new binary is replaced atomically (fixing `ETXTBSY` when overwriting a running file), the new instance starts on a spare port and passes the health check, nginx upstream switches traffic smoothly, the old instance shuts down gracefully, and online users reconnect automatically and catch up incrementally; if any step fails it rolls back to the old instance automatically. install.sh deployments switch to a `modernchat@<port>` template unit; old single-port deployments are migrated automatically on upgrade. Frontend artifacts are also swapped atomically (built to `dist.new`). `--cold` forces the old-style restart.
- **One-command install script (BT Panel style)**: a single command deploys on a fresh Linux server — environment self-check and install of missing packages (Go 1.26 / Node 22 / MySQL 8 / nginx, domestic mirrors can be switched to official sources) → pull the latest code from Gitee → build frontend and backend locally → create the database and account automatically (just fill in connection details for an existing instance) → generate `JWT_SECRET` and `server/.env` → systemd service + nginx config (static hosting / `/api` reverse proxy / `/ws` upgrade) → print the directly accessible site address (domain preferred, otherwise public IP:port). `INSTALL_DIR` / `DOMAIN` / `DB_MODE` and other env vars enable non-interactive use. Usage in ops manual §3.1.
- **Transparent install-script passwords**: the application database password can be preset with `DB_PASS` or customized in the prompt, and is randomly generated if left blank; the install summary **states** the database account and password explicitly (previously it only said "the password is in DB_DSN in server/.env", leaving users none the wiser); when MySQL is installed automatically, the summary notes that root is passwordless (auth_socket) and gives the command to set a root password; install logs are tightened to mode 600 (so plaintext passwords can't be read by other local users).
- **Local cache management in settings**: shows PWA static cache and local preference usage, with one-click clearing of the static cache; login state and appearance preferences are kept.
- **Message-flow reading aids**: a "Back to bottom" button appears at the bottom right when scrolling up through history; new messages arriving meanwhile show "N new messages", and clicking returns to the bottom and marks them read. Sending a message always jumps back to the bottom, so you never lose sight of what you sent.
- **Tab unread indicator**: the title shows `(N) ModernChat` when the chat page has unread messages (muted conversations excluded), returning to the site name on other pages.

### Fixed

- **Completed `server/.env.example`**: ops manual §3.3 manual deployment referenced `cp server/.env.example server/.env` but the file had always been missing, so manual deployers got stuck at step 3. It is now complete (matching all env vars in `config.go` one-to-one, including commented examples for online update `RELEASE_API_URL` / `RELEASE_DL_URL`); also fixed the contradictory rule in `.gitignore` (line 24 `!.env.example` allowed it and line 29 ignored it again, so the example file could never enter the repo).
- **Release package binaries had no executable bit (203/EXEC)**: when packaged on Windows the NTFS files had no POSIX executable bit, so the extracted `bin/modernchat-server` was 0644 and systemd failed with `Permission denied`/`status=203` in an infinite restart loop. Fix: install.sh / the release package's update.sh force `chmod 755` on the binary and update script after extraction; the Go updater also restores permissions after replacing the binary — regardless of the packaging platform, belt and braces.
- **Port prompts were always skipped, breaking deployment**: the port prompt condition was written `[ -n "${X+x}" ]` while the variable was initialized to an empty string at the start, making the condition always true — `SITE_PORT`/`BACKEND_PORT` stayed empty and were never asked for. Consequences: systemd enabled the template unit itself `modernchat@.service` (rejected by systemd, install aborted at the service stage), nginx generated `listen ;`, and `FRONTEND_URL` became `http://IP:`. Fixed to the `[ -n "$X" ]` check; `PUBLIC_URL` is no longer restored from a resume point (it is derived from `DOMAIN`/`SITE_PORT` each time, avoiding bad leftover values); when resuming at the configuration stage, the `.env` `FRONTEND_URL` is checked against the derived value and rewritten automatically if inconsistent, repairing bad values from old resume points.
- **sha256 verification defeated by Gitee's anti-hotlink page**: fetching the `.sha256` asset used curl without `-L` (the tar.gz download included it), so after Gitee's asset redirect it downloaded an HTML anti-hotlink page and compared that as the checksum list, reporting "expected `<html><body>You`" and aborting the install. Three fixes: the fetches in install.sh and the release package's update.sh now include `-L`; all three places (including the Go updater) first validate that the list is 64 hex digits before comparing, and on anomalies degrade to skipping verification while showing the package's own hash, no longer falsely reporting "tampered".
- **install.sh failed to create the database after auto-installing MySQL (ERROR 1698)**: the pre-check used `mysql -uroot` (Unix socket, where auth_socket applies) and considered passwordless root fine, but database creation forced `--protocol=TCP -h127.0.0.1` — Ubuntu's root@localhost only allows socket auth, so TCP got Access denied. Fix: for a passwordless root targeting the local machine, use the Unix socket (remote instances still use TCP).
- **install.sh skip hints and the --force argument**: the script header comments and progress hints always claimed `--force` reruns everything, but the argument was never parsed (in practice only `FORCE=1` worked); argument parsing is now added. All "skipping completed stage" hints now also explain how to rerun — just that stage (delete the corresponding `STAGE_` line in the state file) or everything (`--force` / `FORCE=1`) — so users no longer see only "skipped" without knowing how to redo it.
- **install.sh aborted on an undefined variable**: under `set -u` it referenced a leftover `$MIRROR` variable from the old "auto-install Go/Node" era (that mechanism was removed with release mode), so a fresh install always aborted with `MIRROR: unbound variable` after the database prompt and never reached downloading the release package. The leftover state-recording line is removed.
- **Notification drawer copy failed to compile**: the Chinese copy for `notify.mentions` / `notify.empty` left `@` unescaped instead of `{'@'}` per vue-i18n syntax, so the whole message failed to compile, drawer rendering threw, and the DOM stayed on "Loading" after loading finished. It is escaped now and browser regression verification was added.

### Performance

- **Image message thumbnails**: when uploading with `kind=image` the server generates a JPEG thumbnail ≤480px (`_t.jpg`, supported for both local and object storage; GIFs and images that are already small are skipped, and transparent images are padded on white), message bubbles load the thumbnail and the lightbox loads the original — traffic and decoding cost drop significantly in image-heavy conversations.
- **Message search FULLTEXT**: `messages.content` gains an ngram full-text index (migration `0022`, with an idempotent fallback at startup); keywords of ≥2 characters use phrase matching, and single characters or index anomalies fall back to LIKE automatically. **Upgrading requires migration 0022** (run at off-peak; index creation does not lock the table).

## [0.10.0] — 2026-11-06

> **Upgrade notes (upgrading from 0.9.x)**
>
> - New migration **`0021_message_sender_index`** (an index on `messages.sender_id`). MySQL 8 uses online DDL by default and doesn't lock the table, but a very large message table still consumes IO; run it at off-peak and watch `SHOW PROCESSLIST`.
> - The front nginx `client_max_body_size` must be ≥ **32 MB**: this version's default video limit is 30 MB, while nginx's default 1 MB returns 413 directly (raise it together when raising the video limit in the admin console).
> - "Email verification required at registration" is **on by default**: after upgrading, new registrations need an email + 6-digit code. Without SMTP it automatically degrades to not required (`GET /api/site` returns the effective value), and the **first account is always exempt**; to return to the old behaviour, turn it off in the admin console under "System settings → Site".
> - If `JWT_SECRET` has been changed, the SMTP / Redis / object storage secrets already encrypted in the admin console must be re-entered (unrelated to this version; an existing constraint).

> Note: some capabilities in this version (message editing, conversation management, group management enhancements, notifications / PWA, backups, etc.) were merged with the tag but missed in the first log; they are recorded now.

### Added

- **Video messages**: a "Video" button in the composer sends a local file directly (mp4 / webm / mov / m4v, ≤30 MB by default, adjustable 1–100 MB in the admin console). Bubbles play inline with the native player and hold a fixed 16:9 placeholder without jitter, supporting quote / forward / favorite / recall. The backend `upload?kind=video` **determines the real type from container characteristics** (`ftyp` brand / Matroska magic; audio-only m4a is rejected), and object storage `Content-Type` is set per audio/video.
- **Email verification at registration**: email + 6-digit code on the registration page (60-second countdown). Codes are valid for 10 minutes, single-use, invalidated after 5 consecutive failures, and only an HMAC-SHA256 hash is stored; `POST /api/auth/email-code` and the `email_codes` table are added (migration `0020`). The admin switch defaults to on, degrades automatically without SMTP, and the first account is exempt.
- **Email rebinding requires verification**: `POST /api/me/email-code` sends a code to the new address; `PATCH /api/me` only persists it and marks it verified after successful verification — preventing someone from changing the email to another person's address (taking over the unique index, sending reset links to the wrong person).
- **Message content search**: `GET /api/search/messages` (LIKE on the body, only conversations the user has joined, excluding recalled / deleted). Two entry points: the list-pane search box searches messages across all conversations, and the detail panel gains a "Search chat history" section (`Ctrl/Cmd+F` focuses it); clicking a result jumps to it and highlights it.
- **TypeScript support for plugins and more extension points**: uploading `.ts` (or installing a URL ending in `.ts`) is transpiled file by file by esbuild on the server and stored, with syntax errors returning 400 including the line number; `registerMessageAction` (message context menu), `conv:read` (`me` / `conv.current` / `conv.members` / `messages.recent`), `ui:host` (`nav.*` / `toast`), and three declarative UI components `table` / `progress` / `badge` are added. Types in `plugins/modernchat-sdk.d.ts`, a development guide in `docs/插件开发.md`, and an example `plugins/examples/conv-stats.plugin.ts`.
- **Media messages**: entries for images (canvas compression to a max side of 1600 before sending, webp q0.82) and voice (`MediaRecorder`, click to start / click again to stop, 60-second limit); messages store only URLs, and the URL must belong to this site's storage before it is persisted.
- **Stickers**: a personal sticker library (`stickers`, URLs only), one click in the panel sends directly, with upload (≤2 MB) and deletion support; messages render as transparent images.
- **IM experience enhancements**: quote replies (a quote block above the bubble, clicking jumps back to the original message), `@` mentions (member picker + highlight + `mention_unread`), pinning (server-side personal setting, cross-device), mute (the red dot becomes a plain dot), drafts (kept when switching conversations and shown as `[Draft]` in the list), image context menu (view full size / save / favorite).
- **Message editing**: the "Edit" context-menu item is visible only for the user's own **text messages within 5 minutes that are not recalled**; WS `edit` uplink, `message_update` broadcast, `messages.edited_at` persisted, and "Edited" displayed.
- **Message reliability and multi-device sync**: direct-chat delivery status (`delivered` / `message_delivered`), multi-device read sync, incremental catch-up after reconnect (deduplicated by `clientMsgId`, no full re-fetch).
- **Conversation management**: archive / unarchive conversations; remove a conversation from your own list (without leaving the group or deleting messages); clear personal chat history (only your own watermark is set, the messages themselves are kept).
- **Content moderation**: blocking users (bidirectional blocking of messages and friend requests), message reporting (once per user per message, reason 1–200 characters), administrator deletion of violating messages (removed on all clients), sensitive-word filtering in the admin console (messages containing a match are rejected).
- **Group capabilities**: group announcements (published/edited/revoked by the owner, ≤500 characters, pushed in realtime), group files (≤20 MB, type whitelist **excluding html / svg** to prevent stored XSS, deletable by the uploader or owner), group admin role, member muting (10 minutes – 30 days), mute-all, group avatar, group invite links (valid for 7 days) and friend invites.
- **Registration invite codes**: batch generation in the admin console (count / validity / up to 20 per batch), atomic consumption via a conditional database UPDATE, no over-issuance under concurrency, quota refunded automatically if registration fails; disabled codes are not deleted so the audit trail is kept.
- **Login lockout after failures**: failures accumulate per account (atomic increment), with a temporary lock at the threshold; the threshold and duration are configurable in the admin console (0 = off); cleared as soon as the credentials are correct.
- **Maintenance mode**: one switch in the admin console shows non-administrators only a maintenance page (customizable copy); REST returns 503 and WS refuses non-admin connections. Administrators can always sign in and access the admin console; `/api/site`, `/api/health`, `/api/version`, `/auth/login` remain available.
- **Site-wide announcement popups + initial public chat room**: online users see a popup immediately; announcements missed while offline pop up on the next visit to the chat page (only once per announcement); on first startup a "Public chat room" is created and includes existing users, and new registrations join automatically (users who leave are not pulled back).
- **Desktop notifications + PWA**: browser desktop notifications, a notification drawer, and a Service Worker caching static assets (the app shell survives offline).
- **Web Push**: once VAPID is configured, pushes arrive even with the page closed; silently skipped when not configured.
- **Admin console enhancements**: overview statistics, user filtering, user details (online state / conversation count / message count), force logout, site-wide announcements, role adjustments (demoting the last site admin is forbidden), force uninstalling a plugin by name, an audit tab, storage statistics and orphan file cleanup.
- **Site admin backups**: "Back up now" and a backup file list in the admin console; optional scheduled backups and retention count (`BACKUP_INTERVAL_HOURS` / `BACKUP_RETAIN`).
- **Observability**: Prometheus `GET /api/metrics`, protected by `METRICS_TOKEN`.
- **Ops configuration takes effect immediately**: site (name / registration switch), chat rules (message length / recall window / group member limit) and upload limits (images / voice / group files / **video**) take effect as soon as they are saved in the admin console, with out-of-range values returning an explicit 400; a new public `GET /api/site` endpoint for the frontend to consume uniformly.
- **UI and experience foundations**: the four-column layout can be dragged to resize, and double-clicking a divider toggles "persistent / drawer" (width and mode persisted); site-wide page background customization (preset colors / color picker / local image + four textures, entry only on the settings page); Apple-style motion and material tokens; TDesign → UnoCSS + 13 in-house `Ui*` controls; static assets emitted as `.gz` / `.br` at build time (first screen 161 KB → about 65 KB).
- **File storage abstraction**: the `service.Storage` interface plus local / S3-compatible implementations (minio-go, compatible with AWS S3 / MinIO / OSS / COS); configured visually in the admin console and stored AES-256-GCM encrypted, with keys never echoed back; when object storage is configured, failures are reported explicitly with no silent fallback to local.
- Docs: `docs/设计文档.md`, `后端需求规格.md`, `前端技术方案.md`, `运维手册.md`, `UI设计方案.md`, `插件开发.md`.

### Changed

- **Emoji reactions not yet enabled**: the emoji reaction entry under message bubbles is hidden (`FEATURES.reactions = false`; the code is kept and setting it back to `true` enables it). Per the design doc it is scheduled for phase two; this phase only covers custom sticker **sending**.
- **Recall notices disappear automatically after 3 minutes**: the recall time is issued by the server and persisted (`messages.recalled_at`), consistent across refreshes / devices; legacy recalled messages without a timestamp are treated as expired.
- **Information architecture reorganized**: the icon rail went from 6 items to 4 (avatar / chats / contacts / settings), add friend and create group moved to a permanent spot at the top of the list pane, and plugin management and the admin console moved into the settings page.
- **Empty-conversation placeholder uses the product favicon**, matching the browser tab icon.

### Fixed

- **Conversation detail drawer was unclickable**: the drawer layout class had been applied to multiple root `DetailPanel` sub-components and was silently lost, so the panel had no `z-index` and was covered by the full-screen scrim (visible but not clickable), and the tablet "drawer expands when visible" behaviour failed too. `ChatLayout`'s own container now carries the layout class.
- **Recall consistency**: unread bubble counts, quote-block snapshots, edit state and conversation previews were out of sync in five places; they are now corrected together with the `recall` frame (local unread aligned with the server's `RecallUnreadAdjust`, and the server no longer hard-codes a Chinese preview), and the direct-chat view fills in `lastMessageType` (images/voice no longer show file addresses).
- **Forwarding and merged forwarding**: recalled messages cannot be forwarded (re-validated at send time, preventing content leaks if a message is recalled while the picker is open); merged forwarding skips recalled messages and reports how many, with a maximum of 20 messages (excess is rejected on the spot rather than silently dropped).
- **Message reliability**: merging server messages after reconnect didn't clear `pending`, so delivered messages were wrongly marked "Send failed" 8 seconds later; resending lost quotes and `@`; auto-read was too aggressive (background tabs / scrolling up through history also cleared red dots); "Mark as read" didn't clear "someone @mentioned me".
- **Auth flows**: Enter didn't submit on login/register; a 401 redirect to login lost the origin (it now carries `?redirect=`); `fetch()` network errors surfaced the raw English message; `fetchMe` logged out on any network blip; the first account's email was discarded (so that account could never recover its password); signed-in users clicking the password-recovery link were bounced back to the chat page by the guard; the recovery link carried a `token` that was never read (the flow was dead; it now enters step two automatically and puts the token in the email body as a fallback).
- **Admin settings**: on load failure the form showed defaults but could still be saved (overwriting live configuration; saving is now locked with a retry); key fields gave no indication whether they were configured; profile saving had no dirty check and "changing only the nickname" wiped the email verification state (now submits by diff); one plugin failing to load affected all of them (now isolated individually, a failed start/stop keeps the old runtime, and disabling recollects theme variables).
- **Groups and members**: leaving a group left you on a blank conversation; after an owner transfer the "Delete violating message" entry didn't refresh; a failed member list load gave no hint (now shows an error and retry), member/group-file requests gained race protection so switching conversations no longer mixes data; the group file limit now follows the admin configuration.
- **Message list and search**: jumping to a search result that had since been recalled/expired/deleted silently did nothing and left `pendingJumpId` behind; in multi-select mode images/stickers couldn't be selected; the pinned style in the conversation list did an `O(n)` lookup per row.
- **Other**: page background color only painted the first screen (the solid layer switched to `repeat` and the image layer to `fixed`); an over-quota background image deleted the previously saved one; switching conversations while recording voice sent the recording to the previous conversation; cancelling an edit cleared the original draft; the invite landing page didn't refresh when the token switched; narrow-screen drawers were eaten by `display:none` and tablets kept an invalid divider; the read-only plugin API `messages.recent` leaked recalled original text.

### Performance

- **Conversation list reads an order of magnitude fewer rows**: member counts use a single `GROUP BY` and peer profiles are fetched only for direct chats (20 full groups went from about 4,000 rows per call to a few dozen); group search likewise replaces per-group `COUNT` with one `GROUP BY` (21 round trips → 2).
- **`/api/site` no longer does a full-table `COUNT`**: it uses `SELECT 1 ... LIMIT 1` (that endpoint is called every 30 seconds by every online client); parsed configuration is cached with an `atomic.Pointer` and invalidated synchronously on save.
- **Added the `messages.sender_id` index** (migration `0021`): admin statistics by sender no longer scan the whole table.
- **Frontend**: ordinary `conv_change` events are incremental only (no longer re-fetching the conversation list for every message), site config polling is skipped in the background plus shallow comparison, the conversation list dropped O(n²), plugin code is fetched concurrently, message-area nicknames reuse the member cache, and the virtual list's estimated row height is closer to reality.

### Security

- **Request body size limit** (CWE-770): a `BodyLimit` middleware is added (1 MB by default, relaxed for plugin uploads per `PLUGIN_MAX_SIZE`), returning **413** when exceeded; previously an oversized JSON body to the login endpoint alone could consume a lot of memory.
- **Security response headers**: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`; `deploy/nginx.*.conf` now includes `Permissions-Policy` as well, plus a CSP template (commented out by default — a strict CSP breaks the plugin sandbox).
- **Reset links no longer logged by default**: without SMTP, `LOG_RESET_LINK` defaults to `false` in release mode (a usable token in the logs is an account-takeover entry point).
- **nginx access log disabled for `/ws`**: WebSocket tokens can only go in the query string, and the default `access_log` records the full URI (CWE-598).
- Compression: REST uses `gin-contrib/gzip` (excluding `/ws`, not compressing <1KB), and WS enables `permessage-deflate`.

- **Coverage tooling**: `scripts/coverage.ps1` / `coverage.sh` merge unit & integration coverage and detect "silently skipped" false-green runs
- Unit tests for the backend config / version / mail packages

### Fixed

- **`text/plain` and similar uploads were always rejected**: `http.DetectContentType` returns `text/plain; charset=utf-8` for text, and the parameter made the whitelist never match (images/audio return MIME types without parameters, which is why it had never surfaced). It now strips the parameters after `;` before the lookup. Regression test `TestDetectTypeStripsMimeParameters` added
- **Duplicate migration version numbers**: `chat_prefs_reply_mention` and `system_settings` were both numbered `0005`, and `golang-migrate` indexes by version, causing conflicts/skips. `chat_prefs_reply_mention` is renumbered to `0007`
- **Same friend appearing twice**: `PendingToUser` only queried `status=0 AND friend_id=me` without excluding pairs that are "already friends"; the mutual-request race or historical leftovers made the same person appear in both "friend requests" and "my friends". Changed to a `NOT EXISTS` exclusion plus deduplication by requester, accepting a friend request also cleans up the other pending records for that pair, and the frontend deduplicates as a second layer
- **Favorites opened to a blank screen**: backend `Favorites` used `var rows []`, and with no favorites a nil slice serialized to `null`, so the frontend `items.map()` threw `Cannot read properties of null`. The backend initializes an empty slice with a handler fallback, the frontend store tightens with `Array.isArray()`; the same class of problem in the message list (empty conversation) and friend list is fixed too
- **Message timestamp row was clipped**: `.mc-msg` used `margin` for spacing, while `DynamicScroller` measures items by wrapper height, so margins weren't counted → the meta rows of adjacent messages touched each other; `opacity: 0.9` also created a compositing layer that rendered the 12px text as a blurry ghost. Switched to `padding` with an explicit line height and removed the opacity
- **UnoCSS opacity modifiers didn't work on CSS variables**: `bg-success/12` degenerated to a solid color, and with same-color text it became "green on green" (admin status columns and plugin permission labels were unreadable). Switched to the `color-mix`-predefined `*-soft` / `*-line` steps, 15 places fixed
- **Had admin permission but couldn't enter the admin console**: the route guard read the in-memory `auth.user`, which was empty after a refresh or when visiting `/admin` directly → judged unauthorized and bounced back to the chat page. It now calls `fetchMe()` first when a token exists but the user is empty
- **Detail panel "Leave group" button was squashed into a thin line**: the panel is a flex column that scrolls as a whole, and children default to `flex-shrink: 1`, so it was compressed proportionally as members grew. Added `flex-shrink: 0` to section/footer
- **`<button>` default border looked like a white ring in dark mode**: browsers default to `2px outset`, most visible on input clear buttons. All in-house buttons now have `border-none`, and outlined variants use `border-1 border-solid`
- **Owner transfer didn't sync `owner_id`**: the frontend read `ownerId` for management rights while the backend read the member `role` for permissions, and the two conclusions were opposite → the old owner still saw admin entries (403 on click) and the new owner saw none; now synced within the same transaction
- **Plugin drawer wouldn't open**: TDesign `Drawer` only has a `visible` prop, and a bare `v-model` landed its value on a DOM attribute, leaving the drawer off-screen → switched to `v-model:visible`
- **Trailing space in `FRONTEND_URL` left the slash unstripped**: whitelist mismatched the browser Origin, WS handshake rejected
- **Messages stuck at "sending" while offline**: `ws.send()` now returns a boolean; when the connection is unavailable the optimistic message is marked failed and can be resent
- **No resync after reconnect**: reconnecting now re-fetches the conversation list and the latest messages of the open conversation (merged & deduplicated by `clientMsgId`)
- **Stale "online" dots after disconnect**: the online set is cleared on disconnect
- **Clicking an old conversation after being kicked showed a blank page**: failed conversation open now falls back to the empty state
- **Admin user list couldn't paginate**: the total was overwritten by an unassigned variable
- **Emails not sending**: empty SMTP auth parameters, no 465 implicit TLS support, garbled Chinese subjects, missing timeout protection
- Friend list deduplicated per peer (fixed seeing two rows after adding a friend)
- Scrolling up history no longer replays the entrance animation of the last message
- Avatar / nickname changes sync in real time via WebSocket

### Performance

- TDesign switched to on-demand imports (removed `app.use(TDesign)` global registration), components chunked with their routes: **first-load gzip 262 kB → 104 kB**
- `vite-plugin-vue-devtools` only enabled in development
